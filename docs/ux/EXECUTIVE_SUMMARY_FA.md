# گزارش مدیریتی مرحلهٔ اول ممیزی و بهبود تجربه کاربری سامانه TMS / FanaOne

**کارفرما:** هلدینگ فناوا  
**مخزن:** `Amirhossein2323/fanaone-glpi-custom`  
**تاریخ بررسی:** ۲۴ آبان ۱۴۰۵ / ۱۵ نوامبر ۲۰۲۶  
**وضعیت:** نسخهٔ آزمایشی برای ارزیابی و تأیید (Draft PR #1)

## خلاصهٔ اجرایی
هدف پروژه، کاهش اصطکاک کاربری در فرآیندهای تکراری، کاهش خطاهای انسانی، ارتقای یادگیری کاربران جدید و استانداردسازی رابط کاربری در ماژول‌های GLPI است. در این مرحله، اصلاحات در کامپوننت‌های مشترک پیاده‌سازی شده‌اند؛ بنابراین به‌صورت بالقوه بر چند ماژول اثر دارند، ولی هنوز آزمون عملیاتی همهٔ ماژول‌ها انجام نشده است.

## ایرادهای اصلی شناسایی‌شده در کد
- جست‌وجوی سراسری در عرض‌های باریک به‌صورت پیش‌فرض مخفی بود و ورودی آن خطای نوشتاری در مشخصهٔ `type` داشت.
- جداول نتایج به فیلتر محلی ردیف‌های همان صفحه مجهز نبودند و تعدادی از کنترل‌ها برچسب مناسب برای کاربران صفحه‌کلید/صفحه‌خوان نداشتند.
- هشدارها و خطاها پس از زمان مشخص ناپدید می‌شدند و اطلاع‌رسانی آن‌ها برای همهٔ وضعیت‌ها با فوریت یکسان انجام می‌شد.
- کنترل‌های مرتب‌سازی جدول از طریق کلیک روی سلول سرستون عمل می‌کردند و برای استفادهٔ صفحه‌کلیدی بهینه نبودند.
- فرم‌های طولانی بازخورد مشخصی دربارهٔ تغییرات ذخیره‌نشده و بعضی خطاهای اعتبارسنجی مرورگر نداشتند.
- کدهای اختصاصی CSS در چند لایه قرار گرفته‌اند و خطر ناسازگاری ظاهری دارند.

## اصلاحات پیاده‌سازی‌شده
1. نمایش جست‌وجوی سراسری برای کاربران مجاز در نمایش‌های باریک؛ اصلاح نوع ورودی، برچسب و ارسال جست‌وجو.
2. فیلتر سریع ردیف‌های **صفحهٔ جاری** با پشتیبانی از شکل‌های متداول «ی/ي» و «ک/ك»، شمارندهٔ نتیجه و دکمهٔ پاک‌سازی.
3. بهبود کنترل‌های جداول، برچسب انتخاب سطر و دکمهٔ قابل‌فوکوس برای مرتب‌سازی.
4. ماندگاری خطا و هشدار تا زمان بستن کاربر و اطلاع‌رسانی کم‌مزاحمت‌تر برای پیام‌های عادی.
5. بهتر شدن مدیریت خطای کپی خروجی، نبود مجوز Clipboard و خطاهای درخواست شبکه؛ اصلاح بازگرداندن وضعیت فیلتر پس از شکست عملیات.
6. نوار اقدامات فرم‌های طولانی، نمایش وضعیت و هشدار تغییرات ذخیره‌نشده و راهنمای خطای اعتبارسنجی HTML.
7. بهبود فوکوس صفحه‌کلید، میان‌بر دسترسی سریع به محتوای اصلی، فاصلهٔ کنترل‌ها و رفتار واکنش‌گرا.
8. تدوین استانداردهای مشترک ظاهر و رفتار کامپوننت‌ها و ساخت نمونهٔ HTML تعاملی کتابخانهٔ UI.

## خروجی‌های مستند
- `UX_AUDIT.md`: شواهد کد، سطح ریسک، مشکل و اصلاح پیشنهادی.
- `USER_FLOWS.md`: نقشهٔ قبل/بعد مسیرهای اصلی به‌صورت Mermaid.
- `DESIGN_SYSTEM.md`: توکن‌ها، استاندارد دکمه‌ها، فرم‌ها، جدول‌ها و اعلان‌ها.
- `UI_KIT_PREVIEW.html`: نمونهٔ تعاملی راست‌به‌چپ برای مرور و تأیید بصری، **نه فایل فیگما**.
- `MODULE_COVERAGE.md`: فهرست ماژول‌ها و کارهای باقی‌مانده برای ممیزی میدانی.
- `ACCEPTANCE_TESTS.md`: سناریوها، معیارها و چک‌لیست آزمون پذیرش.
- `tests/ux/fanaone-ux.test.cjs`: تست خودکار فیلتر و وضعیت ذخیره‌نشده.

## معیارهای پذیرش و محدودیت نتیجه‌گیری
**بهبود ۲۰ تا ۳۰ درصدی فعلاً اثبات نشده است.** برای هر تسک کلیدی، تعداد کلیک‌ها، زمان انجام کار، نرخ خطا و امتیاز CES در نسخهٔ قبلی و نسخهٔ جدید باید اندازه‌گیری و مقایسه شود. همچنین «صفر شدن سردرگمی» نیازمند آزمون کاربران واقعی با نقش‌های مختلف است. اجرای موفق تست کد به معنای تأیید تجربهٔ کاربری توسط کاربر نیست.

| محور پذیرش | وضعیت فعلی |
|---|---|
| اصلاح کامپوننت‌های مشترک | کد در شاخهٔ آزمایشی ثبت شده |
| تست خودکار JavaScript | اجرا و موفقیت در GitHub Actions |
| تست مرورگر و GLPI عملیاتی | نیازمند محیط تست معتبر |
| اسکرین‌شات واقعی قبل و بعد | هنوز ثبت نشده |
| آزمون تک‌تک ماژول‌ها و افزونه‌ها | در برنامهٔ آزمون |
| اندازه‌گیری CES و کاهش زمان/کلیک | نیازمند اندازه‌گیری میدانی |
| کتابخانهٔ اختصاصی Figma | ارائه نشده؛ جایگزین HTML در مخزن قرار دارد |

## ریسک فوری امنیتی، مستقل از UX
در نسخهٔ عمومی مخزن، فایل‌های تنظیمات محیط اجرا و کلید رمزنگاری ردپای قابل‌مشاهده دارند. **PR #2** برای جلوگیری از ثبت مجدد و حذف فایل‌های حساس از وضعیت جدید مخزن ساخته شده، ولی حذف آن‌ها از یک کامیت، تاریخچهٔ عمومی را پاک نمی‌کند. کنترل انتشار و بازبینی امنیتی، چرخش امن اطلاعات اتصال و بررسی مهاجرت کلیدهای رمزنگاری ضروری است. ادغام PR امنیتی قبل از تأمین امن فایل‌های لازم روی سرور می‌تواند سرویس را از کار بیندازد.
